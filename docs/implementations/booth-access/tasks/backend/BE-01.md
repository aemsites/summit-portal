## Problem and objective

There is no endpoint that maps an approved attendee's registration email to a prepared website report. Implement an event-scoped lookup that reads only the private roster, establishes short-lived server-side booth context, and lets the browser navigate **directly** to the existing report path. Do not introduce a company confirmation screen.

## Files and ownership

Create `src/booth.js` (staff-selected event context, config and lookup handlers) and `test/booth.test.js`; modify `src/index.js` to route `POST /auth/booth/select`, config, lookup, context and Done. Paths are relative to `workers/cloudflare/cug-adobe-oauth-worker/`. BE-02/BE-03 will extend these files **sequentially**, never in parallel. FE-01 owns its separate block files.

## Deliverables

1. Only signed-in staff can select an active event via `/auth/booth/select`, fetch its presentation/sales config and look up an attendee; anonymous, customer and expired-staff calls are denied. `/booth?event=<id>` is an operator setup hint, not an authentication method. A disabled event denies lookup.
2. Persist a signed/opaque HttpOnly **device event binding** (valid no longer than the staff session) separately from the short-lived, per-attendee HttpOnly context. Redirect setup to clean `/booth`. Normalize the entire email against that event's approved roster. A single valid match returns only the approved report path and sets the attendee context; no bulk records, token or PII logs. Client-supplied event IDs must not switch lookup context after setup.
3. Missing, duplicate, revoked and malformed records fail closed; no result from the general company index. Return neutral UX errors for missing emails, with internal diagnostics that do not expose private data.
4. Return `Cache-Control: private, no-store`; handle excessive repeated lookups without enabling enumeration and test rate-limit behavior through the chosen store.
5. Implement a minimal `GET /auth/booth/context` for the report helper and Finish view and a `POST /auth/booth/done` that clears only the **attendee** context, retaining the device event selection for the next person. An expired or mismatched context cannot identify a different report; browser Back after Done does not restore an active attendee context.
