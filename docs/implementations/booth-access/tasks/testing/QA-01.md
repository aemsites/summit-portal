## Problem and objective

Component tests cannot prove that the vendor touchscreen, staff login, Worker and DA-hosted report work as one experience. Rehearse both a known attendee and failure paths on the final browser/device before any launch claim.

## Read first and follow

- `docs/implementations/booth-access/README.md`, `design/experience.md` and `operations.md`.
- `workers/cloudflare/cug-adobe-oauth-worker/test/booth.test.js`: API cases.
- `test/blocks/booth-access.test.js`: UI cases.
- `AGENTS.md` visual preview and publishing guidance.

## Files and ownership

Create `docs/implementations/booth-access/rehearsal.md`; update approved isolated integration tests only if a specific failing behavior needs regression coverage. No concurrent runtime task should edit those tests during rehearsal. Do not publish real attendee information in screenshots or checked-in fixtures.

## Rehearsal matrix

1. Submit an enrolled email and navigate **directly** to its existing portal-landing page; use its booth-only Finish control to return to the same booth page, then Done. Verify no confirmation/fake report screen exists and that another report path does not gain the toolbar.
2. Try unknown, duplicate, personal/alternate, revoked and wrong-event emails; observe the approved help/error state and no report leakage.
3. Send to matched inbox, retry a mail failure and test link expiry, wrong-report access and revocation according to the signed-off policy.
4. On the vendor's portrait browser, check keyboard, touch, Chrome/Edge back/reload, inactivity, cache, reset, no essential hover, network loss and staff-session expiry. Verify venue internet and whether the screen needs a laptop/media player.
5. Reconcile expected attendee count (roughly 400 for the first event) against approved report assignments; list and resolve missing reports before opening.

## Verification and done

Run `cd workers/cloudflare/cug-adobe-oauth-worker && npm test` and `npm run lint` plus the targeted root UI test and `npm run lint` from repo root; distinguish pre-existing failures from regressions. Record observed dates, environment, results, unresolved exceptions and an explicit owner go/no-go in `rehearsal.md`. This task remains `Blocked` without final hardware/DA access; it cannot pass on mockups alone.
