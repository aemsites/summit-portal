## Problem and objective

The kiosk welcome is only the first screen. The actual prepared report must remain readable and touch-usable in the vendor's 40-inch portrait browser. Existing Adobe/Semrush co-branding is coupled to the Cannes block's theme and should not be copied to all reports by accident.

## Read first and follow

- `blocks/cobrand/cobrand.js:1-28` and `blocks/cobrand/cobrand.css:1-110`: existing partner lockup and Cannes-only theme scope.
- `blocks/report-hero/report-hero.css:177-250`, `blocks/report-carousel/report-carousel.css:119-200`, `blocks/report-stats/report-stats.css:1-120`: block width and content handling.
- `PROJECT.md` sections on report blocks, branding and responsive design.
- `docs/implementations/booth-access/design/experience.md`: sizes and device behavior.
- One **actual** approved report page in the DA preview (the owner supplies the path).

## Files and ownership

Only modify the scoped report styles shown above, and an approved dedicated brand asset if one is needed. Do not edit `blocks/booth-access/` (FE-01/02 own it), Worker files, or `scripts/ak.js`. If the real report demonstrates problems in different blocks, add those exact files to the task scope before editing; this list is a starting hypothesis, not permission to restyle everything.

## Deliverables

1. Inspect the real report at portrait sizes; record measured overflow, touch-target and chart/carousel issues.
2. Correct only observed issues without breaking the existing 1000px mobile/desktop layouts.
3. Review Adobe-only versus Semrush/co-branded assets on the actual report, with brand-owner signoff; separate kiosk chrome from report theming.
4. Re-check mobile and desktop against the portrait CSS changes.

## Verification and done

Run `npx stylelint blocks/cobrand/cobrand.css blocks/report-hero/report-hero.css blocks/report-carousel/report-carousel.css blocks/report-stats/report-stats.css` for files actually edited, then browser snapshot/evaluate on the real approved report at 390 x 844, 1080 x 1920 and 2160 x 3840. Measure document scroll width against viewport and check that report controls remain usable. Finish with `git diff --check`. No claims about portrait readiness based only on the concept brief.
