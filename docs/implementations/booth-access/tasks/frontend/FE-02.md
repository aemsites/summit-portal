# FE-02: Finish and reset the booth session

| Field | Value |
|---|---|
| Domain / size | Frontend / L |
| Wave / stream | 1 / C |
| Dependencies | FE-01, BE-03 |

## Problem and objective

After exploring the report, the attendee needs one reliable way to take it away: email the report link to the registration address already matched by the Worker. A shared device must then return to a clean welcome screen. Give the in-person conversation the visual weight of a handoff rather than a support menu, while sales and 1:1 scheduling remain guidance until the event team defines a real action.

## Deliverables

1. On a real `/accounts/` portal-landing page launched from the booth in the **same tab**, conditionally load a small, persistent "Finish" control after the LCP phase. The report helper checks the server-side attendee context matches the exact **canonical trailing-slash** report path (see `src/index.js:117-125`); a URL flag alone cannot expose the control or a Finish flow. The control returns to the Finish view on **`/booth`** without an email/path in the URL.
2. "Email my report" sends only the matched roster email via BE-03 and clearly distinguishes sending, sent, failure and retry; a repeat tap does not create uncontrolled duplicate emails.
3. Give "Talk through your report here" a prominent, clearly non-interactive Adobe-team handoff; present a later follow-up as secondary guidance. Do not add a booking URL, click handler, fake success state, or button styling without a named owner, actual availability, fallback and approved workflow.
4. "Finish and clear this screen" is visually quiet but remains a usable attendee control. It clears the server-side booth context and visible state; a bounded inactivity reset must work **on the report page as well as on the booth page**, then return to the welcome view. Browser-history/staff-cookie risks remain for kiosk controls, not a false claim of full logout.
5. Browser tests for normal send, failure, repeat tap, absence of sales/scheduling controls, wrong-report/no-context toolbar suppression, back navigation and timed reset.
6. The current concept has **no public example link** on `/booth`. If an approved design later restores one, provide a visible return to the booth welcome from that example path **without requiring an attendee context** and test it in the locked-down browser. Opening an uncloseable extra tab is not a production fallback.
