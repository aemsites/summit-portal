# FE-01: Reusable booth welcome and lookup

| Field | Value |
|---|---|
| Domain / size | Frontend / M |

## Problem and objective

The current login screen offers Adobe ID or a self-service magic link; neither selects a prepared report on a shared touchscreen. Build one reusable EDS block with email entry, loading and failure states. A successful lookup navigates directly to the existing report, without replacing login for ordinary users or adding a confirmation screen.

## Files and ownership

Create `blocks/booth-access/booth-access.js`, `blocks/booth-access/booth-access.css`, and `test/blocks/booth-access.test.js`. Author **one** DA page at `/booth` in the site's existing content system with the block's initial markup; this checkout has no `content/` directory. A local `drafts/booth-access.html` fixture is permitted for preview, not an event-specific production page. Leave the existing root/login experience intact. FE-02 extends the same block/test **after** this task, never in parallel.

## Deliverables

1. A question-led, portrait-first attract state with a large registration-email field, submit loading indicator, explicit not-found/network-error messages and a retry path. The illustrative ambient motion is pausable, stops while email is being entered, and respects reduced-motion preferences. No fabricated live search results, unapproved customer logos, promised score or turnaround.
2. Staff-session and bound-event config check before lookup; if the device is not authenticated or no event is selected, direct an operator to setup/existing staff login instead of displaying a success-shaped empty result. Handle the bookmarked `/booth?event=<id>` operator setup through BE-01, then remove it from the attendee-facing URL. For an unmanaged device, use `/login?staff&redirect=<encoded booth URL>`; the normal `/login` redirect does not request staff mode.
3. On a unique match, navigate in the **same tab** to the Worker-approved portal-landing path (with a non-authorizing booth hint if required). No intermediate company or fake report screen, arbitrary URL input, published roster, or PII in analytics/URL.
4. **Adobe Brand Visibility** in the header in every mode, with the repo's Adobe mark and Adobe Clean font. Adobe-only versus Adobe/Semrush partner chrome is selected from the **server-approved bound-event configuration before email entry**, not user-controlled query params. Resolve the preview's Adobe-red `#EB1000` versus existing site token `#e60000` with the brand owner without recoloring all reports. No event-specific layout code or product rename.
5. Do **not** place the Frescopa example or its link on the attendee Entry screen in the current concept. Retain the real sample asset for staff-led demonstrations if requested. A later attendee-facing example would require explicit approval and a kiosk-safe return path from the example report.
6. Keep the existing product-page QR asset available for **separate booth signage**, not the Entry screen. Signage must label the Adobe product-page destination for a visitor's phone, distinguish it from report access, and be tested for scannability if deployed.

## Verification and done

Run `npx eslint blocks/booth-access/booth-access.js test/blocks/booth-access.test.js`, `npx stylelint blocks/booth-access/booth-access.css` and `npm run test:file -- test/blocks/booth-access.test.js` from repo root. Preview the DA page or local fixture at the **2160 × 3840 event target first**, then fallback and mobile sizes, with motion running, paused and reduced; ensure no horizontal overflow. Done means a valid lookup goes directly to the approved report path, while failed lookups remain on the entry screen.
